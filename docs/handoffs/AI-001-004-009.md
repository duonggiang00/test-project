# Handoff: Milestone 9 — Governed AI generation (AI-001–004, AI-009)

Status: DONE (AI-001, AI-002, AI-003, AI-004, AI-009)
Deferred by owner decision: AI-006, AI-007, AI-008
Risk level: L4 — provider/review architecture; L3 sensitive retrieval and
grading

## Outcome

- Summary: AI content can no longer publish itself. Every generation now
  passes through a persisted, allowlisted review state machine before it can
  reach the live `Question`/`Flashcard`/`TopicBrief` tables; the provider is
  behind a typed abstraction with configurable per-use-case model policy and
  versioned prompts; every provider call and review decision records the
  `ERROR_AND_AUDIT_CONTRACTS.md` §2.4 metadata atomically with its state
  change; rendered prompts and raw output live in a separate restricted store
  under the approved 30-day retention clock, readable only by the owning
  teacher or an admin; and the advisory-grading invariant is established in
  the schema before any AI grading exists.
- Requirements/task IDs: AI-001 (DONE), AI-002 (DONE), AI-003 (DONE),
  AI-004 (DONE), AI-009 (DONE). AI-005 was already DONE from Batch B.
- Deferred: AI-006/007/008 (golden dataset, evaluation runner, CI regression
  thresholds). The project owner elected to defer these; they require 30–50
  admin-approved reference cases that, per
  `REMAINING_HIGH_RISK_APPROVAL_PACKET.md` §7, no agent may invent or
  self-approve.

## Independent review and remediation

A reviewer agent read all eight commits in full, traced every invariant
against the literal code, and re-ran all four suites itself.

1. **P1 — auto-publish escape.** The upload-time bypass fix had covered only
   one of the two background workers in `ai_service.py`.
   `mock_generate_topic_kit` still wrote `topic.brief_content` and a live
   `FlashcardDeck`/`Flashcard` set directly, so
   `POST /flashcards/ai/generate-topic-kit` published AI content to students
   with no approval and — because it closed with `commit_with_admin_override`,
   which fires only for a non-owning admin — no audit row at all on the
   ordinary owner-teacher path. Fixed in `6723c62`: it now parks two
   reviewable jobs (brief, flashcards) at `awaiting_review`, with a
   regression test asserting no live row appears and the brief materializes
   only after approve-then-publish.
2. **P2 — unaudited chat.** The chat path called the provider while recording
   none of the §2.4 metadata and, on the common path, no audit event at all,
   leaving chat spend unreconstructable. Fixed in the same commit with
   `ai.chat.requested`.

The reviewer separately verified and found clean: publish reads only the
reviewed draft; `ALLOWED_TRANSITIONS` has no `generated → published` path;
the earlier refused-publish-still-published bug is genuinely fixed with a
regression test; both redaction barriers hold under attack; restricted-payload
cross-tenant reads are indistinguishable 404s; the purge allowlist did not
loosen; the SDK is confined to one file by an enforced (not baselined) rule;
no frontend code calls a removed route and the UI cannot offer an action the
backend would 409; `GradingService` was not altered.

## Impact

- API/event/schema contract: Five additive review routes. **Breaking:** the
  three `POST /materials/{id}/save-*` routes were removed — they were the
  bypass, and a thin wrapper would have kept it with extra steps. The
  frontend was rewired in the same milestone. OpenAPI grew 56 → 58 paths.
- Migration/data: Two additive heads, `c4e1a70b58d9` and `e7b21c9d4a83`.
  Neither backfills.
- Security/ownership/tenant: Review is owner-teacher-or-admin only through
  the existing policy layer; the reviewer is always the acting request's
  actor, never inferred from the owner. Restricted payloads inherit the
  parent job's authorization. Cross-owner probes are canonical 404s
  throughout.
- Dependency/toolchain: No new dependency.

## Known risks and follow-up

- **AI-006/007/008 remain TODO** and gate any claim that AI quality is
  measured. Hard safety invariants (no cross-owner retrieval, no automatic
  publication, no final AI grading) are enforced in code and tested; quality,
  groundedness, injection-resistance, latency, and cost are **not** measured
  yet. Do not represent this milestone as making AI output *good* — it makes
  AI output *governed*.
- **AI-009 has no production caller.** `AIGradeSuggestion` and its service
  exist and are tested, but nothing generates a suggestion yet, so the
  advisory invariant currently holds trivially. When AI grading is
  implemented, the apply-on-approval path described in the model docstring
  still needs building. Flagged by the reviewer as P3.
- The redaction canary test asserts the outcome (no canary in any audit row)
  rather than probing `validate_audit_action_event` directly with a
  prompt-shaped key on an `ai.generation.*` action. Both barriers were
  manually verified by the reviewer, but a direct negative fixture would be
  stronger. Reviewer P3.
- Estimated cost is `null` unless `AI_TOKEN_PRICING` is configured. This is
  deliberate — a hardcoded rate would look authoritative while silently going
  stale — but it means cost reporting is inert until an operator supplies an
  approved price list. Token counts are always recorded so cost is
  reconstructable.
- The frontend publish control cannot yet choose a destination topic; it
  always sends `topic_id: null` and falls back to the material's topic.
  Reviewer P3.
- Pre-existing and out of scope: the admin sidebar is desktop-only and the
  mobile hamburger has no handler, so there is no in-product path to admin
  routes on a phone.

## Rollback

- Code: revert the relevant commit(s). The additive tables may safely remain.
- Configuration: generation can be disabled without deleting review or audit
  rows.
- Data: never downgrade a shared database to roll back provider code. Pending
  jobs should be moved to `failed`/`rejected` with an audited reason rather
  than deleted; the review-state downgrade refuses while rows exist for
  exactly this reason.
