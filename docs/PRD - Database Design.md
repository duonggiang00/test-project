# **Product Requirements Document (PRD): Database Design**

**Project Name:** Online Quiz System with AI Question Generation

**Target Completion:** 3-4 Weeks (Student Project Scale)

**Database Engine:** PostgreSQL

**Version:** 1.0

## **1\. Introduction**

### **1.1 Purpose**

This document outlines the database architecture and schema for a lightweight Online Quiz System. The system supports manual exam creation and an automated, AI-assisted question generation workflow by parsing uploaded study materials (PDF, Word, Text, Markdown).

### **1.2 Target Audience**

* **Developers:** To implement the schema using an ORM (e.g., SQLAlchemy) and design corresponding Repository/Service layers.  
* **Instructors (Admin/Teachers):** Users who upload documents, generate quizzes, and manage exams.  
* **Students:** Users who take the exams and view their results.

### **1.3 Key Objectives**

* Provide a robust relational structure for exams, questions, and answers.  
* Track the provenance of AI-generated questions back to their source study materials.  
* Maintain a clear separation between quiz structure (master data) and student attempts (transactional data).  
* Keep the complexity manageable for a 3-4 week development timeline (target: \~7 core tables).

## **2\. Database Architecture (Entity-Relationship)**

The database is logically divided into four modules:

1. **Identity:** User authentication and role management.  
2. **Knowledge Base:** Storage of study materials and AI processing status.  
3. **Quiz Structure:** The core entities defining exams, questions, and options.  
4. **Execution & Grading:** Tracking student attempts and detailed answers.

## **3\. Detailed Schema Specification**

### **Module 1: Identity**

#### **Table: users**

Stores all platform users. Roles dictate permissions (e.g., only 'teacher' can create exams).

| Column Name | Data Type | Constraints | Description |
| :---- | :---- | :---- | :---- |
| id | UUID | PK, Default gen\_random\_uuid() | Unique identifier |
| email | VARCHAR(255) | UNIQUE, NOT NULL | User's email for login |
| password\_hash | VARCHAR(255) | NOT NULL | Hashed password |
| full\_name | VARCHAR(100) |  | Display name |
| role | VARCHAR(20) | Default 'student' | e.g., 'admin', 'teacher', 'student' |
| created\_at | TIMESTAMPTZ | Default NOW() | Record creation timestamp |

### **Module 2: Knowledge Base (AI Input)**

#### **Table: study\_materials**

Stores metadata and parsed text from documents uploaded for AI processing.

| Column Name | Data Type | Constraints | Description |
| :---- | :---- | :---- | :---- |
| id | UUID | PK, Default gen\_random\_uuid() | Unique identifier |
| uploader\_id | UUID | FK \-\> users(id) ON DELETE CASCADE | The user who uploaded the file |
| title | VARCHAR(255) | NOT NULL | Display name of the document |
| file\_type | VARCHAR(10) | NOT NULL | 'pdf', 'docx', 'txt', 'md' |
| file\_path | VARCHAR(500) | NOT NULL | Path on disk or cloud storage URI |
| parsed\_text | TEXT |  | Extracted raw text sent to the LLM |
| ai\_status | VARCHAR(20) | Default 'pending' | 'pending', 'processing', 'completed', 'failed' |
| created\_at | TIMESTAMPTZ | Default NOW() | Record creation timestamp |

### **Module 3: Quiz Structure**

#### **Table: exams**

Represents a specific quiz or test event.

| Column Name | Data Type | Constraints | Description |
| :---- | :---- | :---- | :---- |
| id | UUID | PK, Default gen\_random\_uuid() | Unique identifier |
| creator\_id | UUID | FK \-\> users(id) ON DELETE CASCADE | Teacher who created the exam |
| title | VARCHAR(255) | NOT NULL | Exam title |
| description | TEXT |  | Instructions or syllabus |
| duration\_minutes | INT | NOT NULL, Default 60 | Allowed time to complete |
| is\_published | BOOLEAN | Default FALSE | TRUE means students can take it |
| created\_at | TIMESTAMPTZ | Default NOW() | Record creation timestamp |

#### **Table: questions**

Individual questions belonging to an exam. Links back to study\_materials if generated by AI.

| Column Name | Data Type | Constraints | Description |
| :---- | :---- | :---- | :---- |
| id | UUID | PK, Default gen\_random\_uuid() | Unique identifier |
| exam\_id | UUID | FK \-\> exams(id) ON DELETE CASCADE | Which exam this belongs to |
| material\_id | UUID | FK \-\> study\_materials(id) ON DELETE SET NULL | Source material (null if manually created) |
| content | TEXT | NOT NULL | The actual question text |
| is\_ai\_generated | BOOLEAN | Default FALSE | Flag for auditing AI content |
| points | INT | Default 1 | Score value of the question |
| created\_at | TIMESTAMPTZ | Default NOW() | Record creation timestamp |

#### **Table: options**

The multiple-choice answers for a specific question.

| Column Name | Data Type | Constraints | Description |
| :---- | :---- | :---- | :---- |
| id | UUID | PK, Default gen\_random\_uuid() | Unique identifier |
| question\_id | UUID | FK \-\> questions(id) ON DELETE CASCADE | The question this option belongs to |
| content | TEXT | NOT NULL | The text of the answer choice |
| is\_correct | BOOLEAN | NOT NULL, Default FALSE | Indicates if this is the correct answer |

### **Module 4: Execution & Grading**

#### **Table: submissions**

Tracks a student's attempt at an exam.

| Column Name | Data Type | Constraints | Description |
| :---- | :---- | :---- | :---- |
| id | UUID | PK, Default gen\_random\_uuid() | Unique identifier |
| exam\_id | UUID | FK \-\> exams(id) ON DELETE CASCADE | The exam being taken |
| student\_id | UUID | FK \-\> users(id) ON DELETE CASCADE | The student taking the exam |
| start\_time | TIMESTAMPTZ | NOT NULL, Default NOW() | When the student started |
| end\_time | TIMESTAMPTZ |  | When the student submitted |
| total\_score | INT | Default 0 | Calculated final score |
| status | VARCHAR(20) | Default 'in\_progress' | 'in\_progress', 'submitted', 'abandoned' |
| *Constraint:* UNIQUE(exam\_id, student\_id) \- Limits a student to one attempt per exam. |  |  |  |

#### **Table: submission\_answers**

Records the specific option a student chose for each question during their attempt.

| Column Name | Data Type | Constraints | Description |
| :---- | :---- | :---- | :---- |
| id | UUID | PK, Default gen\_random\_uuid() | Unique identifier |
| submission\_id | UUID | FK \-\> submissions(id) ON DELETE CASCADE | Link to the specific attempt |
| question\_id | UUID | FK \-\> questions(id) ON DELETE CASCADE | The question answered |
| selected\_option\_id | UUID | FK \-\> options(id) ON DELETE CASCADE | The answer the student picked |
| is\_correct | BOOLEAN |  | Snapshot of correctness at time of grading |
| *Constraint:* UNIQUE(submission\_id, question\_id) \- A student can only select one answer per question. |  |  |  |

## **4\. Development & Implementation Notes**

### **4.1 AI Integration Workflow (Simplified)**

To maintain the 3-4 week timeline, avoid external message brokers (like Celery/RabbitMQ).

1. **Upload:** Teacher uploads a file via API. System saves it, extracts text, and creates a study\_materials record (ai\_status \= 'pending').  
2. **Background Process:** Use FastAPI's BackgroundTasks to send the parsed\_text to the AI (e.g., OpenAI API) asking for a JSON array of questions and options.  
3. **Update State:** Upon AI completion, the background task parses the JSON, creates records in questions and options, and updates the study\_materials record (ai\_status \= 'completed').

### **4.2 Security Considerations (Crucial)**

* When students fetch an exam (GET /exams/{id}/questions), the API **MUST NOT** return the is\_correct field from the options table. Use Pydantic response models to strip this data before it reaches the frontend.  
* Scoring should happen entirely server-side when calculating submissions.total\_score.

### **4.3 Scalability & Future Scope (Out of Scope for V1)**

* Multiple correct answers per question.  
* Fill-in-the-blank question types.  
* Detailed AI generation logs (separate tables).  
* Role-Based Access Control (RBAC) tables instead of simple string roles.
